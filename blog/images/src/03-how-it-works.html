What actually moves between agents

Everything is written to .mixai/ on your machine. No cloud, no API keys, no model call.

1 · Read the session

mixai parses the agent's own local session log — the objective, the conversation, what was tried.

→

2 · Snapshot the work

Branch, HEAD, git status, and a patch of your uncommitted changes.

→

3 · Write a checkpoint

A portable handoff bundle on disk. Pure file I/O — costs literally zero tokens.

→

4 · Launch the next agent

Opened with a continuation prompt pointing straight at the checkpoint.

.mixai/current/ — the handoff bundle
BRIEF.md
Tiny always-on context: current objective + git state
HANDOFF.md
Objective, last outcome, recent conversation, memory
TRANSCRIPT.md
The full extracted conversation, if more detail is needed
WORKSPACE.patch
Your tracked changes as a diff
memory.db
SQLite: decisions, digests, FTS5 search index
Memory

Never starts from scratch

  • Every checkpoint is indexed into local SQLite and distilled into durable facts
  • Decisions and constraints never expire; routine chatter gets compressed
  • Any agent can answer "why did we choose Postgres?" without re-reading history
  • Full-text FTS5 + BM25 search, plus semantic search if Ollama is running
Token budget

Small on purpose

  • Recent history stays verbatim; older history folds into compact digests
  • Search returns previews, not walls of text — drill in only if needed
  • code_outline / code_find_references replace reading whole files
  • A ledger reports measured savings — not marketing percentages
Result: context that survives quota limits, context resets, and agent switches alike.
